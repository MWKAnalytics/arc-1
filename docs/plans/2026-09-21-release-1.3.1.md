# Release 1.3.1 — preparation and hold

Durable record carried by main-bound #813. The candidate discussed below is #811;
its manual commits and PR body are not the durable source for this hold.

## What this candidate contains

release-please generated #811 from `main`. The only release-triggering change since 1.3.0 is
[#807](https://github.com/arc-mcp/arc-1/pull/807) (reuse the Connectivity proxy client for stateful
sessions); the dependency bumps merged since are `chore(deps)`, hidden from the changelog. #813,
#809 and #828 are **not** in this candidate.

## Hold

Do not publish this head. Merge #813, #809 and #828 first, let release-please regenerate #811,
reconcile the 1.3.1 notes, and revalidate the resulting head.

Do not use `workflow_dispatch` on `release.yml` to refresh the PR: `publish-npm` runs on
`release_created || github.event_name == 'workflow_dispatch'`, so a manual dispatch publishes the
package.

## Annotation belongs on main, not on this branch

release-please rebuilds this branch from `main` with `force: true`
([`GitHub.updatePullRequest`](https://github.com/googleapis/release-please/blob/v17.6.0/src/github.ts)
→ code-suggester `createPullRequest`), so every manual commit here is discarded the next time a
`fix:` merges and the changelog content changes — which the hold above guarantees will happen.
Past releases only kept their annotation because nothing merged between writing it and merging the
release PR (1.2.0: release commit 11:32 UTC, annotation 11:36, merged straight after).

`.claude/commands/release-notes.md` now records that rule. #813 seeds the `## 1.3.1` section on
`main` and carries the #807 row, so this branch's own release-notes hunk becomes a no-op once #813
merges and release-please regenerates. The release-notes CI guard only proves the *version* is
annotated — a lost row is silent, which is why the rows are not left here.

## Reconciliation checklist before release

1. #813, #809 and #828 merged; release-please has regenerated #811 from the new `main`.
2. `docs_page/release-notes.md` on `main` has one `## 1.3.1` section with a row per merged fix —
   #807 and #813 arrive with #813; #809 (server-driven where-used routing) and #828 (legacy ADT
   discovery / CTS evidence) still need theirs. Include #678 and its upgrade guidance if that
   PR is merged before the release.
3. Replace `(unreleased)` in the heading with the release date.
4. Rerun the full gate on the regenerated head: `npm test`, typecheck, build, lint,
   `validate:policy`, `check:sizes`, MTA validation, strict docs, packed-npm smoke.
